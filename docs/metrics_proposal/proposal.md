# 論文掲載用: 測定項目の提案

本システム（階層型エッジAIシステム）の有効性を示すために、以下の指標を測定・掲載することを推奨します。

## 1. ESP32 (エッジカメラ) の評価指標

省電力性と信頼性が重要です。

### A. 処理時間と消費電力 (Time & Power)

バッテリー寿命に直結する「Active Time (稼働時間)」の内訳を測定します。
すでに `camera.ino` に実装済みの `[PERF]` ログで計測可能です。

| 項目 | 説明 | 単位 | 意義 |
| :--- | :--- | :--- | :--- |
| **Total Active Time** | Deep Sleep復帰から再スリープまでの全時間 | ms | バッテリー寿命の理論計算に必須。最も重要な指標。 |
| **Capture Time** | カメラの初期化〜撮影保存にかかる時間 | ms | 撮影処理のオーバーヘッド評価。 |
| **Wi-Fi Connect Time** | Wi-Fi接続確立にかかる時間 | ms | 通信環境による変動要因。RSSIとの相関分析が可能。 |
| **Upload Time** | Piへのデータ転送にかかる時間 | ms | データサイズと通信速度の評価。 |

### B. 通信品質 (Connection Quality)

| 項目 | 説明 | 単位 | 意義 |
| :--- | :--- | :--- | :--- |
| **RSSI** | Wi-Fi信号強度 | dBm | 設置場所による通信安定性の指標。Upload Timeとの相関を示すグラフを作ると良い。 |
| **Success Rate** | (成功回数 / 全試行回数) | % | システムの稼働安定性。 |

---

## 2. Raspberry Pi (エッジサーバー) の評価指標

処理能力と、「不要なデータをクラウドに送らない」というフィルタリング効果が重要です。

### A. 推論処理性能 (Inference Performance)

Piがボトルネックになっていないか、リアルタイム性を評価します。
`pi/main.py` のログで計測可能です。

| 項目 | 説明 | 単位 | 意義 |
| :--- | :--- | :--- | :--- |
| **Inference Time** | YOLOによる物体検出にかかる時間 (1枚あたり) | ms | エッジAIの処理能力評価。モデル(YOLOv5n/sなど)ごとの比較も有効。 |
| **Total Processing Time** | 画像受信〜推論〜(転送判定)までの時間 | ms | システム全体の遅延(レイテンシ)評価。 |
| **Concurrency** | 複数台ESPからの同時接続時の安定性 | 台数 | スケーラビリティの検証 (例: 3台同時接続時の遅延増加量)。 |

### B. データ削減効果 (Data Reduction Efficiency)

本システムの最大のメリットである「通信量削減」を定量的に示します。

| 項目 | 説明 | 単位 | 意義 |
| :--- | :--- | :--- | :--- |
| **Input Images** | ESP32から受信した画像総数 | 枚/Byte | 元のデータ量。 |
| **Output Images** | クラウド(本サーバー)へ転送した画像数 | 枚/Byte | 削減後のデータ量。 |
| **Reduction Ratio** | `(1 - Output/Input) * 100` | % | **最も強力な指標**。例: 「画像の90%をエッジで破棄し、通信コストを1/10にした」と主張できる。 |

### C. 検出精度 (Detection Accuracy)

エッジでのフィルタリングが正しく機能しているか。

| 項目 | 説明 | 単位 | 意義 |
| :--- | :--- | :--- | :--- |
| **Precision / Recall** | エッジ側での検出精度 | % | 誤検出(False Positive)で無駄な転送をしていないか、取り逃がし(False Negative)がないか。 |

---

## 3. 実験設定の提案 (Experimental Setup)

論文に記載するための実験条件案です。

1. **比較実験**:
    * **Baseline**: 全画像をそのままクラウドへ送信するシステム (仮想的な比較対象)
    * **Proposed**: 今回のシステム (ESP -> Pi -> Cloud)
    * **結果**: 通信量(Byte)と消費電力(推定)の比較グラフを作成。

2. **スケーラビリティ実験**:
    * ESP32を 1台, 2台, 3台... と増やした時の Pi の CPU負荷 (`htop`などで監視) や推論遅延の推移を計測。

これらの数値は、現在のログ (`metrics.csv`, `edge_metrics.csv`) から集計可能です。
不足している場合は追加実装します。
