# 実装計画: エッジサーバー処理時間の計測

## 目的

エッジサーバーが1サイクル（3枚の画像）を処理するのにかかる時間を計測し、記録する。
各主要ステップ（保存、推論、ロジック判定、転送）の所要時間と、サイクルの合計時間をミリ秒単位で把握できるようにする。

## 変更内容

### `pi/main.py`

#### [MODIFY] [main.py](file:///c:/Users/kapib/vscodegit/wild_animals/test2/pi/main.py)

以下のステップに計測用のコードを追加する：

1. **画像の受信と保存**:
    * `upload_image` 関数の開始からファイル保存完了までの時間を計測する。
    * 「受信開始時刻」と「保存所要時間」をバックグラウンドタスク（`process_image`）に渡す。

2. **推論 (物体検出)**:
    * `process_image` 内で、`detector.detect` の実行にかかる時間を計測する。

3. **サイクル判定と転送**:
    * `CycleManager` にて、サイクルが開始した時刻（1枚目の画像処理開始時）と終了した時刻（3枚目の画像処理完了時）を追跡する。
    * 転送条件を満たした場合、転送処理にかかる時間を計測する。

4. **ロギング**:
    * `logger.info` を使用し、`[PERF]` タグを付けて計測結果をミリ秒単位で出力する。
    * サイクル完了時に、そのサイクル全体の合計所要時間を出力する。

**`CycleManager` のデータ構造変更**:

* 各サイクルの状態に `start_time` を追加し、最初の画像が到着した時刻を記録する。
* サイクル内の各画像の `inference_time` や `save_time` を蓄積し、内訳がわかるようにする。

## 検証計画

### 自動テスト

* ローカルでサーバーを起動する。
* スクリプト（`test_client.py` または `verify_integration.py`）を使用して、3枚の画像を連続して送信する。
* ログファイルを解析し、`[PERF]` タグ付きのエントリが出力されていること、計算された時間が妥当であることを確認する。

### 手動検証

* `edge_server.log` を開き、詳細なミリ秒単位の計測ログを目視で確認する。
