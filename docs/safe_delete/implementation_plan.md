# 削除機能 (Safe Delete) の堅牢化・パフォーマンス改善計画

既存の削除機能 (`delete_cycle`) に存在していた「誤削除リスク」と「パフォーマンス劣化」を解消するための改修計画です。

## User Review Required
> [!IMPORTANT]
> - 本計画では、既存の挙動を踏襲して**安全な「物理削除（完全削除）」**のロジックに置き換えます（サーバー容量の確保を優先するため）。
> - もし「間違って消した時のために『ゴミ箱機能（論理削除フラグ）』にしたい」というご要望があれば、計画を変更しますのでお知らせください。

## Proposed Changes

### original_server

#### [MODIFY] [server.py](file:///c:/Users/kapib/vscodegit/wild_animals/test2/original_server/server.py)
1. **メタデータ主導の削除ロジックへの変更 (`delete_cycle` メソッド)**:
   - `os.listdir` によるディレクトリの全ファイル探索を完全に廃止します。
   - 削除対象となるイベントのメタデータ (`event_metadata.json`) をロードし、そこに記録されている `images` のファイル名と、`get_video_relpaths_for_event()` によって特定した対象動画ファイル名だけをリストアップします。
   - 抽出したファイルの絶対パスを構築し、それらに対してのみ `os.remove` を実行します。これにより、誤削除のリスクをゼロにし、処理時間を数万件のファイルがあっても瞬時（O(1)）で完了させます。

2. **エラーハンドリングの強化（安全な削除の担保）**:
   - ファイル群の削除中に「権限エラー」や「既にファイルがない」などの例外が発生してもサーバー処理全体がクラッシュしないよう、個々のファイル削除に対して `try-except` による保護とエラーロギング（警告）を導入します。

3. **シーケンス制御の明瞭化**:
   - 削除対象が最新イベントであった場合にのみシーケンス番号（`current_server_seq`）を巻き戻す現在のロジックは維持しますが、エッジ側からの再同期（欠番対応）の観点から、影響を限定的にするためのコメントとセーフガードを追加します。
