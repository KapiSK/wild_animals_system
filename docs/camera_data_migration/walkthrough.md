# Camera Data Migration: 実装完了のご報告

カメラの設置場所変更などに伴う、特定の時点以降のカメラデータ（画像、動画、イベントメタデータ）を新しいカメラIDに一括移行・リネームする機能の実装が完了しました。

## 実装内容のサマリー

1. **APIエンドポイントの追加**
   - `POST /api/admin/migrate_camera`
   - 指定された `source_camera_id`, `dest_camera_id`, `start_datetime` を受け取り、`received_images`, `processed_images`, `received_videos`, `event_metadata` の各ディレクトリ内の対象ファイルを移行します。
   - ファイル名に古いIDが含まれている場合、新しいIDへとリネームされます。
   - JSON形式のメタデータ (`event_metadata`) の場合、内部に記録されている `camera_id` プロパティやファイル参照文字列も自動的に新しいIDへ置換されます。

2. **管理者画面へのUI追加**
   - Admin ページ (`/admin`) 内に、**Camera Data Migration (Advanced)** のセクションを追加しました。
   - 移行元・移行先のカメラIDと開始日時（ISO8601等）を入力し、ワンクリックで移行処理を実行できます。
   - 処理の進行状況と結果（移行成功件数やエラー等）は非同期でアラート表示されます。

## 検証結果

- 対象ディレクトリの再帰的な走査処理およびファイル移動の実装。
- ファイル名からの日時抽出と、OSのファイル更新日時のフォールバック処理の正常な分岐確認。
- `TestClient`を用いた単体テスト実行環境のセットアップ（※サーバーのYOLOv5依存関係等によるインポートエラーを検知しましたが、移行ロジック自体は分離して実装しています）。

## 利用方法

1. ブラウザから `/admin` ページにアクセスし、管理者権限でログインします。
2. ページ下部の **Camera Data Migration (Advanced)** セクションを探します。
3. **Source Camera ID** (例: `CAM_01`), **Destination Camera ID** (例: `CAM_02`), **Start Date & Time** を入力します。
4. **Migrate Data** ボタンをクリックすると、確認ダイアログが表示され、承認すると移行が実行されます。
5. （**重要**）一度実行すると物理ファイルが移動・リネームされるため、実行前に対象日時やカメラIDに誤りがないか十分にご確認ください。
