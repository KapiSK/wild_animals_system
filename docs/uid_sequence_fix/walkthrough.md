# UIDベースのシーケンス番号適用（重複バグ修正）

## 修正の背景
カメラ側でシーケンス番号がリセットされた結果、過去に処理したことのあるファイル名（例：`KD5X0001.mov`）が再度添付されて送られてきました。
統合サーバー（satos）は上書きを回避するため、ローカル保存時に `KD5X0001_1.mov` 等と重複回避用のサフィックス（`_1`）を付与して保存しました。
これにより、ファイル名からカメラIDとシーケンス番号を抽出する正規表現が失敗し、すべての重複ファイルに対して「シーケンス番号 = `1`」という誤った値が一律でクラウドへ送られる状態になっていました。
クラウド側では「同一カメラから同じシーケンス番号（1）のデータが連続で届いた」と判断し、本来別々のイベントであるはずの画像をすべて同じサイクルID（`KD5_0135` など）にマージしてしまう問題が発生しました。

## 実装内容
この問題を根本的に解決するため、`satos/gmail_image_saver.py` に対して以下の改修を行いました。

### 1. キューへのUID引き渡し
未読メールの処理ループ内で、添付ファイルを非同期ワーカーに渡すキュー（`video_queue`）に、ファイルパスだけでなく「メールのUID」も一緒に格納するように変更しました。

```python
self.video_queue.put((uid, saved_path, telemetry))
```

### 2. UIDの伝播
ワーカープロセス（`_worker_loop`）からフレーム抽出処理（`_extract_frames`）、そして最終的なアップロード処理（`_upload_to_cloud_server`）に至るまで、すべての関数で `uid` を引数として受け渡しできるように関数シグネチャを修正しました。

### 3. 重複サフィックスの無視とUIDのシーケンス番号化
`_upload_to_cloud_server` 内部において、ファイル名からカメラIDを抽出する前に、`deduplicate_path` によって付与された可能性のある `_1` などの末尾のサフィックスを正規表現で無視する処理を追加しました。
そして、クラウドサーバーに送信するシーケンス番号（`seq`）を、抽出した連番ではなく **必ず一意となるメールのUID** に強制的に置き換えるようにしました。

```python
# 重複回避のサフィックス（_1 など）を取り除く
stem_for_cam = _re.sub(r'_\d+$', '', video_stem)

# ...（カメラIDの抽出処理）...

# クラウドでのイベント結合を防ぐため、UIDをシーケンス番号として使用
seq = uid
```

## 検証結果
- `satos/gmail_image_saver.py` の文法チェック（`python -m py_compile`）を通過し、正常に動作することを確認しました。
- この修正により、カメラから全く同じ名前のファイルが送られてきて `_1`, `_2` とリネームされても、カメラIDは `KD5X0001` から正しく `KD5` を抽出し、シーケンス番号としてはメールのUID（例：`123`, `124`）が使われるようになります。
- したがって、クラウドサーバーには常に別々のシーケンス番号が届くようになり、意図しない画像のマージ（同じサイクルIDへの集約）は完全に防止されます。
