# Calendar View Implementation Plan

## 1. 目的 (Objective)
ギャラリー画面に第3の表示モードとして「カレンダー（Calendar）」を追加し、日付ベースで動物の出現傾向を視覚的に把握・検索できる仕組みを構築します。

## 2. 変更内容 (Proposed Changes)

### 2.1 UIの追加
- **タブの追加**: ギャラリー画面上部の切り替えボタンに「Calendar」を追加します。（`Grouped` | `Flat` | `Calendar`）
- **カレンダーの描画**: CSS Gridを利用し、月間カレンダーを描画します。
  - カレンダー上部には「◀ 2026年 5月 ▶」のような月切り替えボタンを配置します。

### 2.2 日付マス（セル）のデザイン詳細
各日付のマスには、その日に発生したイベント（サイクル）の情報を集約して表示します。

1. **代表画像**: その日で最も検知の確度が高かった（あるいは最新の）サムネイル画像を、マスの背景または上部に配置します。
2. **検知件数バッジ**: その日に何回サイクルが発生したかを数字バッジで表示します（例: `🔥 5件`）。
3. **検知ラベルアイコン**: 視認性を高めるため、検知されたラベル（文字列）を絵文字に変換して表示します。
   - 例: `animal` → 🐾, `person` → 👤, `vehicle` → 🚙, その他固有動物（deer, bear等）のラベルがあれば該当の動物絵文字。

### 2.3 インタラクション（クリック時の動作）
- カレンダーのマスをクリックすると、カレンダーのすぐ下（または画面下部）に **「〇月〇日の検知リスト」** というエリアが展開されます。
- そこには、先ほど実装した「全体表示（Flatモード）」と全く同じUI（動画再生可能、ページネーション対応）で、その日のサイクルだけが絞り込まれてズラッと並びます。

### 2.4 バックエンド・フロントエンドの処理
- バックエンド（Python）側へのAPI追加は不要です。
- フロントエンド（JavaScript）側で、すでに取得済みのすべてのサイクルデータとメタデータ（`cycle_time`）を使って、月ごとの集計とカレンダーのHTML生成を行います。（動作が非常に高速になります）

## 3. 確認事項 (Open Questions / User Review)
> [!IMPORTANT]
> 1. **ラベルのアイコン化**: 現在AIが返している `labels` の文字列（例：`animal` や `person` など）に心当たりはありますでしょうか？ カレンダー上で見やすくするために、よく出るラベル文字列に絵文字を割り当てたいと考えています。
> 2. **代表画像**: カレンダーのマス内にサムネイル画像を表示すると見栄えは良くなりますが、マスのサイズが少し大きくなります（スマホだと縦長になる）。画像付きにするか、日付とアイコン・件数だけのシンプルなマスにするか、ご希望はありますか？

## 4. 確認手順 (Verification Plan)
1. ギャラリー上部の「Calendar」タブでカレンダーが表示されることを確認する。
2. 前月/次月へ正しく切り替わることを確認する。
3. イベントがあった日付のマスに情報が正しく表示されることを確認する。
4. 日付をクリックした際、その日のサイクルだけが正しく下に展開されることを確認する。
